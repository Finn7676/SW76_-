# tyhh：自适应分裂与避碰 C++ Bot

此目录基于 `xxqz_cpp`，使用同一套地图记忆、局部 BFS、候选评估和碰撞模拟。当前版本增加了可见敌方头部的预测惩罚：中大型地图避免进入敌方下一步可能到达的格子；`arena` 这类小地图关闭该惩罚，避免过度保守。前期持续扩张，长度 4–5 的龙负责分裂；长度达到 6 后自动成为核心长龙，不再主动分裂。至少维持 20 条存活龙或达到 320 round 前保持扩张，之后优先选择开放空间和珍珠路径保存长度；完全受困时仍允许紧急分裂。

长度为 2 的最短龙有条件地承担拦截任务：只有己方仍有其他存活龙，且视野内确认敌方某条龙的可见节段数已经超过自身长度时，才会在敌方头部就在下一格时主动兑子。远距离目标不进行追猎，因为敌方下一回合可以改变方向。由于 7×7 视野可能只看到敌龙的一部分，可见节段数只作为保守下界；看不出敌方确实更长时不会主动兑子。

- 每条龙维护独立的可见地图、珍珠位置和珍珠倒计时记忆；
- 优先追踪当前视野内珍珠，其次追踪记忆中的珍珠和近期生成点；
- 避开海带、可见龙身和已知自身身体；
- 局部 BFS（深度 12、最多 220 个节点）寻找珍珠和探索目标；
- 逐步模拟移动的碰撞、尾部变化、吃珠和冲刺支付规则；
- 记录可见边和传送门端点，对未知传送门采取保守策略；
- 根据邻域开放程度、珍珠、倒计时和探索价值给候选移动打分，并识别局部死胡同；
- 在地图较小且长度、人口满足条件时分裂；
- 无合法候选时使用保底移动。

由于 Python 原版依赖运行时字典和异常回退，C++ 版将这些部分改写为显式结构。当前决策器和 Python 原版一样通常输出一步移动；多步动作的规则被用于模拟和合法性评估。传送门的未知出口采取保守跳过策略。

## 当前实验结果

与 `xxqz_cpp` 串行对战，使用 `CXX=clang++` 构建：

| 地图 | 结果 | 结束方式 |
|---|---|---|
| `arena.map` | `tyhh` 胜 | 第 108 回合淘汰 |
| `default.map` | `tyhh` 胜 | 500 回合按长度 |
| `Colosseum.map` | `tyhh` 胜 | 第 29 回合淘汰 |
| `schooltime.map` | `tyhh` 胜 | 500 回合按长度 |
| `big_empty.map` | `xxqz_cpp` 胜 | 第 431 回合淘汰 |

加入相邻头部拦截逻辑后的单局回归为：`arena` 第 108 回合淘汰获胜，`Colosseum` 第 29 回合淘汰获胜，`default` 500 回合按长度获胜，`schooltime` 500 回合按长度获胜；`big_empty` 仍需继续优化。

`tyhh_core`、`tyhh_population`、`tyhh_role`、`tyhh_predict` 和 `tyhh_big*` 是保留的独立实验变体；对应回放与日志位于 `artifacts/opt/`。`big_empty` 仍是未解决的压力用例，主要问题是该图上双方单位数迅速接近上限后，短龙碰撞和总长度差异累积。

运行：

```bash
CXX=clang++ unswbc run maps_BeforeSprinter/arena.map tyhh xxqz_cpp \
  -o artifacts/tyhh_vs_xxqz_cpp.replay
```
