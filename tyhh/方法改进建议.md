# tyhh 方法改进建议

## 总体判断

当前 `tyhh` 已具备较好的规则模拟基础：逐步碰撞检查、尾部变化、珍珠消耗、局部 BFS、传送门端点记忆和分阶段分裂策略都已经实现，具体见 [main.cpp](/home/tyhh/SW76_-/tyhh/main.cpp:47)。

主要瓶颈不在单步评分，而在三类问题：

1. 局部信息没有形成稳定的全局状态；
2. `big_empty`、`help` 等高人口地图中缺少拥挤控制；
3. 终局目标没有显式转化为“保护最长龙、最大化存活长度”。

实验记录还存在不一致：当前 README 将 `big_empty` 写为胜利，但已有日志显示 `team B wins after 431 rounds`。若 `tyhh` 为 Team A，则实际是失败。正式调参前应统一实验统计口径。

## 按规则提出的改进建议

### 1. 7×7 视野：建立敌方轨迹

当前敌方信息只在本回合通过 `occupied` 和 `enemy_head_risk()` 使用，视野外敌方立即消失，见 [main.cpp](/home/tyhh/SW76_-/tyhh/main.cpp:134)。

建议增加：

```cpp
struct EnemyTrack {
    int id;
    Position last_position;
    Direction heading;
    int last_seen_round;
    int visible_length;
    std::unordered_set<Position, PosHash> reachable;
    double confidence;
};
```

每回合从上次位置扩展敌方可达区域，加入环绕移动、已知传送门、海带和已知身体阻挡，以及敌方当前长度允许的冲刺范围。风险评估不再只惩罚“敌头下一格”，而是惩罚进入敌方可达集合的格子。

### 2. 身体与碰撞：修正弯曲身体重建

当前自身身体重建主要沿着头部朝向反向直线搜索：

```cpp
Position next = mem.step(cursor, facing.get_opposite());
```

见 [main.cpp](/home/tyhh/SW76_-/tyhh/main.cpp:56)。这对转弯后的身体不可靠，可能造成空位误判、自身身体漏判以及错误的 BFS 和分裂判断。

应利用每个身体节段自身的 `dir`。身体节段的方向指向头部，因此从头部开始，沿“当前节段方向的反方向”逐节追踪。对于不可见部分，再使用上一回合身体序列进行低置信度补全。

这是优先级最高的确定性修复之一。

### 3. 冲刺：从“只模拟”升级为“受控使用”

当前程序通常只输出一步移动，多步动作仅用于模拟。规则允许冲刺用于穿过安全空旷区域、抢先吃珠、脱离敌方威胁以及进入传送门后的逃生通道。

可以加入深度为 2 的动作候选：

```text
单步移动
两步移动
分裂
```

两步动作必须满足：

- 每一步都通过碰撞检查；
- 每一步都重新计算身体长度；
- 终点有足够开放空间；
- 冲刺后的长度不低于安全阈值；
- 第二步收益明显高于单步移动。

不建议一开始加入更深搜索，以免增加超时风险。

### 4. 珍珠倒计时：从“最近珍珠”改为“到达时机”

当前 `choose_target()` 优先选择当前可见珍珠，再选择记忆珍珠和近期生成点，见 [main.cpp](/home/tyhh/SW76_-/tyhh/main.cpp:119)。但它没有计算：

```text
到达回合 = 当前回合 + 路径长度
等待时间 = 生成回合 - 到达回合
```

建议将目标评分改为：

```text
pearl_score =
    珍珠收益
    - 路径长度惩罚
    - 敌方竞争风险
    - 等待成本
    + 生成时机匹配奖励
```

为记忆中的珍珠增加 `last_observed_round` 和 `confidence`。当前未看见珍珠时不会立即清除旧记忆，容易把过期珍珠继续当成目标。建议观察到无珍珠时立即删除，长时间未观察到的位置降低置信度；`pearl_time == -1` 时不参与生成预测；对称位置共享倒计时，但不直接假设对称位置为空。

### 5. 分裂：由固定阈值改为收益判断

当前存在较强的固定规则，例如扩张阶段长度为 4 时直接分裂，见 [main.cpp](/home/tyhh/SW76_-/tyhh/main.cpp:184)。这在狭窄地图可能有效，但在 `big_empty` 或 `help` 中会造成大量短龙，增加自撞、头部相撞、无效探索和掉落资源被敌方收集的风险。

分裂决策可改为：

```text
split_gain =
    新增探索头部收益
    + 珍珠覆盖收益
    + 敌方封锁收益
    - 父体长度损失
    - 子体出生碰撞风险
    - 人口拥挤风险
```

应加入分裂冷却时间、出生位置至少两个安全出口、当前单位数相对地图面积的密度、旗舰龙状态以及终局阶段判断。

### 6. 死亡与掉落：加入资源转移价值

规则中长度为 `L` 的龙死亡后会掉落 `ceil(L / 2)` 颗珍珠。当前评分主要关注自身移动安全和珍珠，没有显式估计死亡掉落价值。

可以为攻击和兑子增加：

```text
kill_value =
    敌方预计掉落珍珠
    + 消除敌方最长龙的终局收益
    - 己方损失
    - 头部相撞风险
```

长度为 2 的龙主动兑子仍然可以保留，但应进一步判断己方剩余单位数、敌方是否为旗舰龙、掉落区域是否可被己方占领，以及兑子是否会造成己方通道堵塞。

### 7. 行动顺序：利用 ID 和延迟

当前代码没有显式使用行动顺序。规则规定低 ID 先行动，高 ID 后行动，这会影响敌方是否已经移动、头部相撞的可预测性、声呐到达时间以及传送门出口是否已被占据。

建议在敌方风险模型中加入：

```text
if enemy_id < self_id:
    enemy may already have acted
else:
    enemy may still move this round
```

靠近敌方头部时，低 ID 和高 ID 使用不同的风险系数。

### 8. 声呐：先启用低风险的位置同步

`helper.hpp` 已提供 `get_sonar_messages()` 和 `send_sonar()`，但 `tyhh` 没有使用，见 [helper.hpp](/home/tyhh/SW76_-/tyhh/helper.hpp:371)。

建议分三阶段启用：

1. 发送己方坐标、方向、长度等级和角色；
2. 发送敌方头部观测；
3. 发送传送门和珍珠信息。

声呐消息不能直接覆盖视觉信息，因为没有发送者身份，敌方也能收到，消息存在延迟且可能被伪造。建议将信息分为：

```text
Observed      // 视觉事实
TeammateSeen  // 声呐传来的队友信息
Inferred      // 对称性和轨迹推断
```

只允许 `Observed` 直接用于碰撞判定。

### 9. 对称性：补上地图推断

当前 `tyhh` 没有实现题目中的地图对称性利用。规则保证地图具有水平镜像、垂直镜像或 180° 旋转对称性。

建议维护三个候选变换：

```text
reflect_x
reflect_y
rotate_180
```

每次观察到静态边后删除不一致候选。当候选唯一时，可用于推测未探索区域的海带、普通通路、珍珠生成位置和部分传送门端点。

对称推断只能作为低置信度通行信息，不能直接等价为安全区域。建议使用显式枚举，不要复制裸 bit 设计。

### 10. 传送门：允许进入已知传送门

当前候选移动中明确排除了 `kind == "portal"`：

```cpp
if (!dest_opt || kind == "kelp" || kind == "portal" || kind == "unknown_portal")
    continue;
```

见 [main.cpp](/home/tyhh/SW76_-/tyhh/main.cpp:148)。这意味着即使传送门两端已经确认，程序也不会主动从当前格进入传送门。BFS 可能经过传送门，但第一步决策会把它过滤掉。

建议区分：

- `known portal`：允许进入，并评估出口安全；
- `partial portal`：允许作为探索动作，但增加风险；
- `unknown portal`：普通情况下禁止，紧急逃生时允许。

传送门出口附近存在敌方头部时应提高风险，并将传送门后的真实距离纳入 BFS。

### 11. 探索：用信息收益替代最近前沿

当前探索目标是从 `mem.seen` 的边界中选最近未探索格，见 [main.cpp](/home/tyhh/SW76_-/tyhh/main.cpp:123)。

建议将探索收益定义为：

```text
新格子数量
+ 新边数量
+ 新传送门数量
+ 可消除的对称性候选数量
+ 新珍珠计时器数量
```

不同单位可分配不同角色：资源龙优先珍珠，探索龙优先信息收益，旗舰龙优先安全和长度，拦截龙优先敌方路径和传送门出口。当前所有龙共享相近的目标逻辑，容易导致集群式移动和局部拥挤。

### 12. `big_empty` 与 `help`：增加人口密度控制

失败日志中的主要死亡原因集中在：

- `hit itself`；
- `hit another dragon`；
- `lost a head-to-head`。

建议加入全局拥挤指标：

```text
density = 己方单位数 × 平均长度 / 地图面积
```

当密度过高时：

- 停止主动分裂；
- 降低珍珠权重；
- 增加邻域开放度权重；
- 禁止多条龙追逐同一珍珠；
- 为每条龙设置空间扇区或探索方向；
- 让短龙主动远离旗舰龙；
- 对头部相邻区域使用更高惩罚。

`big_empty` 不应继续使用与普通地图相同的珍珠优先逻辑。

### 13. 终局评分：显式保护旗舰龙

当前后期仅将指标字符串改为 `"survive"`，但候选评分主体基本不变，见 [main.cpp](/home/tyhh/SW76_-/tyhh/main.cpp:177)。

建议从第 350 回合开始：

- 长度最高的龙进入旗舰状态；
- 旗舰龙禁止主动进入未知区域；
- 旗舰龙降低珍珠追逐风险；
- 其他短龙负责占位、侦察和兑子；
- 评分中加入预计 500 回合时的最长存活长度。

终局目标应按以下顺序排列：

```text
最大化旗舰龙长度
其次最大化旗舰龙存活概率
最后才是总单位数
```

### 14. 工程可靠性：避免保底动作直接自杀

当前异常处理为：

```cpp
catch (...) { fallback(ct); }
```

而 `fallback()` 在没有候选时直接输出 `NORTH`，见 [main.cpp](/home/tyhh/SW76_-/tyhh/main.cpp:160)。如果北方是海带、身体或未知传送门，这个保底动作可能直接导致死亡。

建议：

- 异常发生后重新生成所有合法单步；
- 至少检查海带、自身身体和可见龙；
- 若所有动作未知，选择已知可通过边；
- 将异常原因和回合写入低成本指标；
- 对动作输出增加本地合法性断言；
- 控制每回合日志量，避免超时。

## 推荐实施顺序

### P0：确定性修复

1. 修正弯曲身体重建；
2. 修正过期珍珠记忆；
3. 允许进入已知传送门；
4. 改造安全保底动作；
5. 统一 `big_empty` 和其他地图的实验结果。

### P1：直接针对当前失败案例

1. 加入地图人口密度；
2. 加入分裂冷却与空间出口判断；
3. 建立敌方可达区域；
4. 实现多单位目标去重；
5. 增加旗舰保护。

### P2：增强信息利用

1. 对称性推断；
2. 敌方轨迹；
3. 珍珠到达时机；
4. 受控两步冲刺；
5. 声呐位置同步。

## 建议的单变量实验

| 实验 | 唯一变化 | 主要验证地图 | 核心指标 |
|---|---|---|---|
| A0 | 当前版本 | 全部地图 | 胜率、失败回合 |
| A1 | 修正身体链重建 | `default_small`、`big_empty` | 自撞率 |
| A2 | 已知传送门可进入 | `arena`、`Colosseum` | 传送门利用率、胜率 |
| A3 | 珍珠记忆过期机制 | `default`、`schooltime` | 平均长度、无效追珠率 |
| A4 | 动态人口密度控制 | `big_empty`、`help` | 单位存活曲线、碰撞死亡数 |
| A5 | 敌方可达区域风险 | `default`、`trophy` | 头部相撞次数 |
| A6 | 旗舰保护策略 | `default`、`big_empty` | 最长存活龙长度 |
| A7 | 受控两步冲刺 | `arena`、`schooltime` | 珍珠数、死亡率 |
| A8 | 声呐位置同步 | `big_empty`、`help` | 重复探索率、胜率 |

建议每张地图至少进行 8 局，双方各作为 Team A 和 Team B。正式提交前扩大到每图 20 局以上，并记录：胜负、结束回合、最长龙长度、总长度、存活单位数、自撞数量、头部相撞数量、撞敌身体数量、分裂次数和珍珠获取数。

运行形式可以沿用：

```bash
python3 benchmark.py tyhh tyhh_variant \
  --maps arena Colosseum default_small default schooltime trophy queen_of_spades big_empty help \
  --games 8
```

当前最值得立即实现的是：身体链重建、已知传送门进入、人口密度控制和旗舰保护。这四项对现有失败模式的针对性最强，且不需要引入复杂学习模型。
