# V05 — Baseline and instrumentation

Status: V05 implemented in `Version05_sketch`. Version04 remains the frozen reference. The next roadmap phase is V06 (unified perception), which is not implemented here.

## Behavior contract

No strategy, target priority, split threshold, search budget, collision rule or sonar protocol was changed. The new invariant is that each dragon turn owns a fresh set of diagnostic counters, which no decision function reads. The scope includes exception recovery and emits at most one diagnostic LOG before ENDTURN. A normal build compiles counter hooks out and emits no telemetry.

`main.cpp` owns the diagnostic scope. `debug.hpp` owns the counter schema, optional active collector, formatting and reset. Hooks in memory, sense, navigation, tactics, forage, opening, kamikaze and sonar measure existing work in place. `decide.hpp`, `model.hpp`, `helper.hpp` and all original strategic parameters are unchanged.

## Enable diagnostics

Normal bot / submission build:

```sh
clang++ -std=c++20 -O2 -Wall -Wextra -Wpedantic -Werror main.cpp -o /tmp/v05-release
```

Profiling build:

```sh
clang++ -std=c++20 -O2 -Wall -Wextra -Wpedantic -Werror -DXXQZ_ENABLE_STATS=1 main.cpp -o /tmp/v05-profile
```

`StrategyConfig::debug_stats` defaults to true only in the profiling build. Setting it to false disables collection/output for a scope. In the normal build, setting it true has no effect because hooks are compiled out. Individual functions called outside a `DebugTurn` scope do not collect counters.

The format is one line per turn:

```text
LOG V05_STATS round=... id=... tiles_scanned=... memory_tiles_scanned=... ...
```

These are work counts, not elapsed CPU time or competition bytecode/point measurements. Diagnostic output has a cost; use the default normal build for competition.

## Counter definitions

| Counter group | Meaning |
|---|---|
| tiles_scanned | Sum of memory, sense and broadcast visits to raw visible tiles; repeated visits intentionally count again |
| memory_tiles_scanned / sense_tiles_scanned / broadcast_tiles_scanned | Raw visible-tile visits attributed to each existing scan |
| memory_entries_aged | Entries visited in the ETA, direct-pearl TTL and shared-report TTL passes |
| frontier_cells_checked | Known cells considered when generating exploration frontiers |
| enemy_group_tiles / goal_tiles_scanned | Snapshot cells visited for enemy grouping and route-goal collection |
| pocket_calls / pocket_nodes / pocket_degree_nodes | Flood-fill calls, dequeued cells, and cells visited again to compute degree |
| route_calls / route_nodes / route_expanded | Router invocations (including early exits), discovered nodes including the start, and dequeued nodes |
| tactical_enemy_checks / short_trade_enemy_checks / stalk_enemy_checks / split_enemy_checks | Enemy entries examined by each policy, including entries skipped by later filters |
| escape_calls / escape_edges | Repeated enemy-escape analyses and outgoing edges considered |
| dive_calls / dive_nodes / dive_enemy_checks | Attack-search invocations, dequeued search states, and target-enemy checks |
| sonar_received / sonar_accepted / sonar_sent | Incoming reports examined, reports passing filters (including repeated valid reports), successful sends |
| fallback_calls | Calls to last_resort; this is often normal trapped-state behavior, not a runtime failure |
| exceptions / emergency_defaults | Exceptions caught around act(), and failures of the first exception fallback |

Bot exits, host timeouts, runner timeouts, memory/point failures and engine-reported invalid actions are detected by the benchmark runner. Parse failures before act() cannot be reported by a per-turn collector and are detected externally.

## Repeatable benchmark

From this directory:

```sh
python3 tests/run.py --sanitize
python3 tools/benchmark_v05.py \
  --baseline ../Version04 \
  --maps ../maps/arena.map ../maps/default.map ../maps/big_empty.map ../maps/schooltime.map \
  --output ../replays/v05-new-run
```

The output directory must be new. Keep benchmark output outside the bot source directory: the UNSW toolkit recursively matches included source filenames. `--repeats N` repeats the complete matrix; `--timeout` bounds each match and `--cxx` selects the compiler.

For every map/repeat, the harness runs:

1. Version04 vs Version04 as the reference.
2. V05 normal build vs Version04, then swapped sides.
3. V05 profiling build vs Version04, then swapped sides.

It snapshots bot sources and map bytes, records SHA-256 hashes/compiler version, builds once per mode, saves compressed verbose logs and `.replay` files, and writes `manifest.json` / `summary.json`. Only V05 diagnostic LOG lines are excluded from comparison; MOVE, SPLIT, SONAR, other LOGs, replay labels, drawings and ENDTURN are compared in sequence with round, dragon ID and team. The first mismatch is recorded. Profiling must emit exactly one complete counter record for every candidate turn.

The installed runner exposes no seed switch. These local runs reproduced identical reference traces. Recorded input bytes and repeated checks are the reproducibility mechanism; cross-platform determinism is not assumed.

A crash/timeout/invalid action, malformed result, missing telemetry or changed trace fails the validation even if the candidate wins. Normal collisions remain gameplay events.

## Current architecture audit

Direct local include dependencies (external standard headers omitted):

```text
debug.hpp -> helper.hpp, strategy.hpp
decide.hpp -> forage.hpp, kamikaze.hpp, opening.hpp, sonar.hpp
forage.hpp -> memory.hpp, sense.hpp, navigation.hpp, tactics.hpp
kamikaze.hpp -> sense.hpp
main.cpp -> decide.hpp
memory.hpp -> model.hpp, debug.hpp, strategy.hpp
model.hpp -> helper.hpp
navigation.hpp -> memory.hpp, sense.hpp
opening.hpp -> sense.hpp
sense.hpp -> model.hpp, debug.hpp
sonar.hpp -> memory.hpp
tactics.hpp -> sense.hpp, strategy.hpp
```

The exact turn sequence remains:

```text
update -> DebugTurn begins
  act:
    configure memory if needed
    memory.observe -> receive_sonar -> look
    short_trade -> move and return if found
    find_dive -> move/make_moves and return if found
    want_voluntary && split_two -> broadcast and return
    want_emergency && split_down -> broadcast and return
    choose -> paint/move -> broadcast -> erase consumed target -> return
    last_resort -> move
  catch: record exception -> last_resort -> move
    second catch: record emergency default -> move NORTH
DebugTurn finishes -> ENDTURN
```

Repeated raw scans occur in `Memory::observe`, `look` and `broadcast_pearl`. `collect_enemies` and route-goal collection rescan the snapshot. `pocket` runs a flood fill plus degree pass for each safe first step; the forage BFS and dive BFS are independent. `frontier()` may be called by both greedy goal selection and routing on the same turn. Enemy entries are rechecked by short_trade, dive target selection, voluntary-split policy, stalk selection and candidate tactical_score; enemy_escapes may repeat across candidates.

Persistent state is `memory` (dimensions, seen cells, edges, pearls, timers, observation timestamps, reports, last_round), the helper's game/controller state, and immutable direction/config constants. View, search queues, goals, candidate scores and diagnostic counts are turn-local. There are no persistent roles or navigation-progress state. The collector pointer only identifies the active scope; aggregate statistics live in the external benchmark.

Merge-sensitive interfaces remain `View`/`StepInfo` in sense, Memory and sonar freshness, forage/navigation/tactics scoring inputs, StrategyConfig, and the priority sequence in decide. V05 adds cross-cutting hooks without consolidating those owners; future refactors should preserve the counter meanings or version their schema.
