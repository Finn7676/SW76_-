# tyhh 测试版本实验记录

## 研究问题

本轮测试检验三类规则驱动改动：

1. 探索龙是否应优先获取新区域信息，并在新区域安全分裂；
2. 旗舰保护是否能提高终局最长龙存活率；
3. 拥挤时停止主动分裂、降低珍珠权重、提高开放空间权重，是否能减少碰撞损失。

## 测试版本

| 版本 | 主要变化 | 对应建议 |
|---|---|---|
| `tyhh_explore` | ID 角色探索、前沿优先、探索龙安全分裂 | 11 |
| `tyhh_flagship` | 固定旗舰候选、提高生存权重、旗舰不主动分裂 | 13 |
| `tyhh_explore_density` | 探索龙 + 拥挤控制 + 资源分配 + 扇区方向 + 旗舰候选 | 11、12、13 |
| `tyhh` | 当前版本基线 | baseline |

## 实验设置

- 对手：`xxqz_cpp`；
- 每张地图 2 局；
- 双方各作为 Team A 和 Team B；
- 大图：`big_empty`、`help`、`default`；
- 回归图：`arena`、`Colosseum`、`default_small`；
- 编译器：`clang++`；
- 运行工具：`benchmark.py`。

由于系统默认 `c++` 不支持 `-std=c++20`，本地实验通过临时工具链路径将 `c++` 指向 `clang++`：

```bash
mkdir -p /tmp/clang-toolchain
ln -sf /usr/bin/clang++ /tmp/clang-toolchain/c++
PATH=/tmp/clang-toolchain:$PATH python3 benchmark.py \
  tyhh_test/tyhh_explore_density xxqz_cpp \
  --maps big_empty help default arena Colosseum default_small --games 2
```

## 死亡模式观察

大图第一轮中，当前版本 `tyhh` 的己方死亡数为：`big_empty` 两局 144、155；`help` 两局 2152、1898。综合版本对应为：`big_empty` 101、100；`help` 1969、1870。统计包括自撞、撞其他龙、头部相撞和撞墙，且日志同时保留对手死亡记录，因此这里只比较己方阵营对应的死亡行。

这表明拥挤控制在 `big_empty` 上降低了碰撞损失，但 `help` 仍然存在大规模单位碰撞，当前密度阈值还不足以解决极端人口压力。

## 当前结论

1. 探索角色是本轮最有价值的改动。`tyhh_explore` 在 12 局中取得 11 胜，且没有破坏三张小图的回归结果；但样本量仍不足以进行稳定性结论。
2. 固定 ID 旗舰策略不适合直接使用。`tyhh_flagship` 出现明显阵营偏差，说明角色分配需要声呐协同或基于实际长度动态选举，而不能固定为 `id % 4 == 0`。
3. 综合版本在 `big_empty` 上表现出方向性改善，但 `help` 仍是主要失败场景。应继续降低极端地图人口，或让初始短龙承担远离出生簇的空间分流任务。
4. 当前实现尚未记录“已见格数量、分裂时地图覆盖率、多龙同目标比例、旗舰最长存活长度”等专门指标，下一轮应将这些指标加入低成本统计或离线回放解析。

## 下一轮建议

优先保留 `tyhh_explore_density` 的探索逻辑，撤销固定旗舰规则，改为：

- 通过声呐共享各龙长度和位置；
- 每隔若干回合选举实际长度最高且风险最低的旗舰；
- 旗舰只在自身长度明显落后时允许分裂；
- `help` 地图将拥挤阈值从当前的 5--6 条龙进一步降至 3--4 条龙；
- 对探索龙设置出生后固定的远离方向，减少同一出生区域的头部相撞。

正式决策前，建议每个版本每张地图至少运行 20 局，并固定双方阵营比例。
