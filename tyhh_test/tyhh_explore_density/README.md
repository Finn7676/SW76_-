# tyhh_explore_density

这是综合测试版本，包含建议 11、12 和 13 的第一版可执行实现。

## 变化

- 探索龙优先追踪新区域，并在安全且未拥挤时分裂；
- 使用 `unit_count` 与地图面积构造拥挤状态；
- 拥挤时停止主动分裂，降低珍珠权重，提高开放空间权重；
- 通过珍珠坐标哈希将资源目标分配给不同 ID，减少多龙追逐同一珍珠；
- 根据 ID 选择空间方向，鼓励不同龙向不同扇区移动；
- 对相邻己方头部增加风险惩罚，让短龙主动离开拥挤区域；
- ID 为 `0 mod 4` 的旗舰候选提高生存和开放空间权重，并禁止主动分裂；
- 拥挤状态下提高敌方头部风险惩罚。

## 重要边界

当前 `unit_count` 只能反映本队存活龙数量，不能得到全队真实平均长度；ID 角色也只是确定性近似。该版本用于快速验证机制方向，不应直接视为最终提交策略。

## 验证指标

- 地图已见格数量和新区域进入回合；
- 分裂次数、分裂时单位数和拥挤触发次数；
- 多龙同目标比例；
- 自撞、撞身体、头部相撞数量；
- 旗舰候选最长存活长度、总长度和胜率。

## 初步实验

使用 `xxqz_cpp` 作为对手，每张地图 2 局，双方各作为 Team A 和 Team B：

| 地图组 | 胜负 | 胜率 |
|---|---:|---:|
| `big_empty`、`help`、`default` | 5-1 | 83.3% |
| `arena`、`Colosseum`、`default_small` | 6-0 | 100% |

日志目录：`replays/20260922-112006-75sspwhf`、`replays/20260922-112556-_h649sr1`。相对当前 `tyhh` 在同一批大图上的 4-2，本版本为 5-1；其中 `big_empty` 两局均获胜，但 `help` 仍为 1-1。结果仅是小样本方向性证据。
