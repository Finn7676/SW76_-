# 新规则实验报告

日期：2026-10-03。基于 `tyhh_qos_relay_counter` 新建独立版本；原 counter、
生产版本、V3_portal 和 xxqztest 未修改。使用 experiment-design 与
experiment-loop：测试前登记假设，冻结源码及运行环境，保留负结果并审计回放。

## 规则与评测口径

本次明确使用项目 `.venv-battlecode` 中的 `unswbc 1.2.7`，而非 PATH 中的
旧 `1.1.0`。终局依次比较固定女王长度、最长龙、总长度；A/B 女王分别为
ID 0/1，死亡后不继任。动作初始长度决定免费步数 `ceil(length/4)`，
付费步检查长度先于移动和吃珠，额外移尾发生在普通移动和吃珠之后。

当前排位地图池为17图。每版本：17图 × 2对手 × 双先后手 = 68局。
原十图40局子集单独统计；地图文件同样采用新规则同步的版本，并非旧地图。
固定种子为78001加排位地图索引，同图不同版本、对手和先后手共享种子。
这是每图一个种子的开发样本，不作显著性或稳定战胜结论。

## 实验版本

`tyhh_qos_counter_queen_v127`：从开局明确保护两侧女王；禁止女王主动换头和
献祭，限制常规分裂，保留应急分裂；侦察龙保留探索并优先攻击敌方女王。
女王及长度至少8的龙只通过有已知几何、当前可见空闲落点、续行和空间的门。
修正冲刺投影、同一珍珠不能重复计数，并加入最多4步的免费连续采珠。
这是综合适配包，胜率变化不能单独归因于某个组件。

`tyhh_qos_counter_queen_feed_v127`：只在上一版本上增加女王定向献祭。
允许较短或等长女王接受供养；要求局部连续8回合无敌情、人口至少4、
剩余采集时间充足，以及女王到 donor 原头部有已知可见1至2步路径和续行。
不保证未知敌人安全，也没有预约女王的下一步行动。空动作死亡是主动献祭，
不是程序故障；比赛照常计入。

无平局，无运行失败。三版本204局全部完成，冻结源码、二进制、引擎、地图、

## 失败归因

queen_v127女王终局存活仅7/68局，基线为6/68。其61次女王死亡中，
33次自撞、23次撞头、5次撞身体，死亡前长度中位数为2。
应急分裂仍可能把女王缩到2；保护女王的常规策略没有覆盖这些应急后续动作。
女王死亡回合索引中位数122，早于献祭策略启动回合280。
这些现象支持下一轮优先检查女王应急脱困，而非仅扩大后期献祭力度。

具体回放：portals对xxqztest后手，女王在第110回合索引由长度8分裂为2，
下一回合进入自身颈部死亡；default对V3先手，女王在第60回合索引被撞头杀死。
终局女王均为0时，比赛又回到最长龙和总资源竞争，传送门资源问题仍然重要。
详见 `queen_v127/queen_loss_slices.json` 和下方回放索引。

喂养机制日志触发41次，涉及6局，41名供体均发生预期死亡。
逐事件追踪在40次馈赠后直接观察到女王收集供体旧身体上的珠，共63颗；
这些馈赠局的女王最终存活仅2/6。该证据确认有实际收集，但不代表整条尸体
被收完或献祭保证终局收益。详见 `feed_mechanism.json`；带scan_only和
preorder_check后缀的文件为保留的中间分析，不用于最终机制结论。

## 验证与复现

原生C++专项断言和1.2.7引擎27项微测试通过，覆盖女王分裂/死亡不继任、
免费步数固定、付费前检查、吃珠与移尾顺序，以及门户安全限制。
额外8局judge sandbox检查完成：queen_v127在portals对两对手双侧4局，
feed版在trauma对两对手双侧4局，均无点数/内存超限或运行失败，回放审计通过。
这不等价于全17图sandbox合规或胜率验证；8局不并入主表204局。

原生主实验匹配耗时总和2303.4秒，最多4局并行；完整证据含日志、回放、
源码、二进制和引擎快照约1.1GB。未删除任何失败或负结果。
